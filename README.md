# 图片增强

纯 CPU 的电商图片清晰化工具：一个 `enhance.py` 核心 + 一个双击就开的图形界面。
不加载任何权重、不做生成式重绘，只把**已经在图里的结构**变清楚。

一个文件（`enhance.py`），纯 CPU，无模型、无权重、无显卡要求。

**它做什么**

1. 按图自动判断值不值得处理 —— 白底平坦图直接用原图，不给平台二次压缩添乱
2. 门限保边锐化 —— 只锐有结构的边缘，平坦区增益严格为 0
3. 分区 —— 人物/主体区锐化，暗且中性的物件区保持原样
4. 批量 —— 扫一个目录，跑的跑、跳的跳过，附 CSV 报告

**它不做什么（这些都是刻意的）**

不重建、不重绘、不补细节、不改颜色、不动全局曲线、不生成内容。
只动锐度，且只在有结构的地方动。

为什么强调这一条：早期版本试过接 NR/超分那条路，结论是那条路会重绘内容，
表现就是「糊、颜色不对、失真」。所有失真的源头都来自「让它生成」这件事本身。

## 仓库里有什么（源是源，工具是工具）

**仓库 = 工具本体，一个字节的真实素材都没有。** 磁盘上两者物理隔开：

```
<工作区>\                          ← 不进仓库
├─ 图片增强\                        ← Git 仓库根目录，只有工具
│   ├─ enhance.py    ui.py   启动.bat   README.md   LICENSE
│   ├─ make_sample.py              ← 合成图生成器（仓库里唯一的"图"来源）
│   ├─ 标定\                        ← 本机标定脚本（写死本机路径，已 gitignore）
│   └─ _sample\                     ← 合成图（可随时重生成，已 gitignore）
└─ _本机素材\示例\                   ← 真实测试原图，在仓库**外面**
```

| 进仓库 | 不进仓库 |
|---|---|
| `enhance.py` `ui.py` `启动.bat` `README.md` `LICENSE` `make_sample.py` | 任何真实 `.png`/`.jpg`、`_本机素材/`、`标定/`、`_sample/`、输出目录、`_*.json` |

原因很直接：**工具可以公开，商品素材不可以。** 工具代码里也不含任何指向
具体项目、具体店铺的路径与名字。仓库里的图只有一种来源 —— 现场合成：

```
python make_sample.py
```

## 用法（两种）

**图形界面**（推荐，双击就行）

```
双击「启动.bat」
```

界面里选图 → 选预设 → 点开始。原图只读，输出写到旁边的 `_增强` 文件夹。

按钮一共四个：**开始处理** / **只判定不出图** / **只压缩（对照）** / **跑自检**；
跑完任意一个都能点 **看最新结果** 直接叫系统看图程序打开刚生成的那张。
「只压缩（对照）」不碰像素，只按当前尺寸策略和格式重新编码一遍 —— 它的唯一用途
是**当基准线**：把「原图压到同样尺寸/格式」和「增强后压到同样尺寸/格式」摆在一起，
才知道增强那一步到底值不值。见下面「先看基准线」一节。

默认会**先把长边缩到 750 再锐化、并输出 JPEG** —— 这不是"为了省体积牺牲画质"，
实测两样都更好；不想缩像素的话把「尺寸策略」改成"保持原像素，按该宽度归一"
（效果接近，原始分辨率一个像素不少）。见下面「尺寸策略」一节。

**命令行**

```powershell
# 单张（全自动分流）
python enhance.py -i 图.jpg -o out\ --preset 对比感增强 --shrink 750 --format jpeg

# 界面上那套默认值（先缩到 750 再锐化 + JPEG）
python enhance.py -i 图.jpg -o out\ --shrink 750 --format jpeg

# 不想缩像素，但效果要对齐到 750 显示宽度（保留原始分辨率）
python enhance.py -i 图.jpg -o out\ --display-width 750 --format jpeg

# 要完全不动尺度（历史行为）、要无损
python enhance.py -i 图.jpg -o out\ --preset 全面清晰 --format png

# 批量（一个目录）
python enhance.py -i 我的图目录 -o out\

# 只看判不判，不出图
python enhance.py -i 图.jpg --judge

# 附各亮度档读数
python enhance.py -i 图.jpg -o out\ --report

# 不做分流，一律处理
python enhance.py -i 图.jpg -o out\ --force

# 用预设（等价于界面里选那一档）
python enhance.py -i 图.jpg -o out\ --preset 全面清晰
python enhance.py --list-presets

# ★ 只压缩（对照）：不做任何增强，只重新编码 —— 用来量"增强到底带来了多少"
python enhance.py -i 图.jpg -o out\ --compress-only --format jpeg
python enhance.py -i 图目录 -o out\ --compress-only --shrink 750 --format jpeg

# 自检（不需要外部图，读的是合成样本）
python enhance.py --selftest
```

`-o` 不写的话，单张默认输出到 `out\`，目录默认输出到 `<目录名>_增强\`。

## 预设（七档）

| 预设 | 干什么 | 适用 |
|---|---|---|
| **推荐** | 人物区锐化，暗且中性的物件区保持原图 | 最稳，任何图都不会失真 |
| **暗部更清晰** | 给有纹理的暗部加局部锐化，平坦黑背景不动 | 黑包/黑衣/阴影想更清楚 |
| **救糊图** | 给"发虚发软"的区域补锐度 | 原图本来就偏软 |
| **全面清晰** | 暗部 + 糊区一起开 | 想一次到位 |
| **对比感增强** | 锐化更强 + 额外拉开中等尺度的明暗过渡 | 前几档都"看不出区别"时用；代价见下 |
| **轻微** | 只补一点点 | 图已经很干净 |
| **清晰 + 放大2倍** | 全面清晰 + 2 倍 Lanczos | 要更大尺寸 |

预设是可复现的固定参数，不是"感觉调一下"。每一档的实测读数（HF 高频变化，
区域按坐标定位，含耳环这种小件）：

```
预设            脸    耳环   黑衣   黑包   黑裤   蓝天   亮度漂移   光晕>3
推荐          +40%   +27%   +19%    +9%    +6%    +2%    -0.20%    0.00%
暗部更清晰     +54%   +31%   +41%   +30%   +38%    +3%    -0.28%    0.00%
救糊图        +44%   +31%   +22%   +12%    +9%    +2%    -0.15%    0.00%
全面清晰      +61%   +38%   +46%   +34%   +42%    +3%    -0.27%    0.00%
轻微          +27%   +19%   +15%    +6%    +5%    +1%    -0.20%    0.00%
对比感增强     +75%   +47%   +57%   +42%   +49%    +4%    -0.43%    0.10%
```

前六档三条硬约束全成立：**平坦区零改动、亮度漂移 < 1%、颜色不动**。
第七档把亮度漂移推到 -0.43%（仍在 1% 以内），代价见下一节。

蓝天 +1~4% 不是"爬纹"：那是天光渐变本身的软过渡，在锐化门限带内，
数值小且不随档位放大（档位从轻微到全面清晰只从 +1% 到 +3%），
真实平坦白底（合成样本）是严格 0。颗粒列（平坦区 std 变化）六档全是 1.00x。

过冲/下冲（光晕的来源，按 3×3 邻域量）：**前六档的最大过冲都是 3/255，
超过 3 的像素占比 0.00%** —— 连最猛的「全面清晰」也没有白边黑边；
它把黑包提了 +34%，包里高光却没炸开，靠的就是这道钳位。
「对比感增强」是唯一一档会越线的：最大过冲 9/255、超过 3 的像素 0.40%
（人像图；四张真实商品图上是 0.08%~0.18%）。

## 局部自适应是怎么做的（暗部 / 糊区）

两个问题分开解，都是**逐像素掩膜**，不看全图、不用模型：

**暗部更清晰** —— 掩膜 = 「此处暗」×「此处有结构」。
只看亮度是不够的：纯黑的阴影空洞没有东西可提，硬提只会把噪点拉出来。
所以叠一层局部标准差当结构门。判据相对梯度而不是绝对梯度，
这样暗处纹理才进得来（绝对门限对亮部合适，暗部会被全挡在门外）。

**救糊图** —— 掩膜 = 「细节扛不住重采样」×「有内容」。
判据是**降采样再升采样后的高频损失**：

```
清晰图    损失 0.17 ~ 0.41   （细节丰富，一缩一放丢掉一大半）
糊图      损失 0.05 ~ 0.08   （本来就没细节，丢无可丢）
```

这个量**与内容多少无关**，只与"是否已经糊了"有关，所以整图均匀发虚也认得出来。

标定实测（细节损失中位）：

```
            清晰   模糊0.8   模糊1.5   模糊2.5
人像       0.171    0.114     0.076     0.055
商品图     0.407    0.146     0.047     0.015
文字图     0.229    0.119     0.049     0.023
```

三档单调，三种内容类型都成立。

**物件保护与加成的关系（这里踩过一个坑，写下来）**：
物件保护的初衷是"别把包当脸一起锐"，做法是暗且中性的区域不吃**基础锐化**。
一开始它连暗部/糊区加成一起削了 —— 实测「暗部更清晰」档在黑包/黑裤上
78%~83% 的加成被吃掉，预设名字写着"更清楚"，拿到的却是接近推荐档的数字。
现在两者分开：**基础锐化被物件保护挡，单独算出来的加成不挡**。
所以黑包该被保护的原样被保护（不爬纹），而"这里暗且有纹理"该拿的清晰度照拿。

**能补回多少（实测，别抱不切实际的期望）**：unsharp 的物理上限大约是 ——
轻糊（sigma 0.8）能补到 **~75%**，中度（1.5）**~33%**，重度（2.5）**~15%**。
再往上加只会出光晕和假边，不会真的把信息变回来。

## 「对比感增强」是怎么来的（为什么前六档"看不出区别"）

这是被同一个反馈逼出来的：**"跟原图差不多，看不出区别"**。

先把图按频段拆开量了一遍。锐化把**像素级锐度**提了 +46%，但人眼判断
"清不清楚"主要看的是**中等尺度**的明暗过渡 ——

```
频段              占图能量     锐化动它吗
极高频 sigma 0.7     0.7%       ★ 主要动这里（像素级"硬"）
高频   sigma 2.0     6.9%         部分
中频   sigma 8.0    34.8%       几乎不动  ← 人眼看的就这段
低频   sigma 24     57.6%       不动
```

⇒ 所以"看不出区别"不是错觉，是**量在了错的地方**。前六档全部只动极高频。

**第七档做的事**：在中频也拉开明暗过渡，但它不是简单的"加对比"——
朴素的高斯中频增益**必然出光晕**，实测：

```
中频 gain 0.5  ⇒  局部对比 +40%，光晕像素 15.0%
中频 gain 0.7  ⇒  局部对比 +59%，光晕像素 28.6%
```

所以用了保边分解 + 三道门：

```
lc = 导引滤波(小窗) - 导引滤波(大窗)     ← 只取中等尺度，不含边缘
边缘门：强边处增益归零（光晕只出在强边两侧）
平坦门：局部起伏过小的地方不动（天空/白底/渐变的底线）
```

**结果**：四张真实商品图上局部对比 +4.4%~+8.0%，而光晕像素只有 0.08%~0.18%。

### 顺带修掉的两个窗口尺度 bug

「平坦区一个字节都不动」是这个工具的底线，做这一档时发现底线破了两次，
**根因是同一个：拿太大的窗口去判断"这里有没有内容"**。

```
判断"这里是不是平坦"用的窗口        灰渐变        真实包面       能分开吗
61px（原）                       0.0472        0.0697       差 1.5 倍 ✗
 9px（改后）                     0.0073        0.0234       差 3.2 倍 ✓
```

缓坡渐变在**小窗口内几乎是平的**，只有真纹理才有局部起伏。61px 的窗口
把跨几十像素的缓坡也当成了"有内容"，于是渐变被改了色阶（实测 7 个）。

同一个根因还坑了暗部档的结构门（41px → 9px）。改后各区域门值：

```
        脸      耳环     黑衣     黑包     黑裤     灰渐变
旧     0.111   0.017   0.396   0.472   0.420   0.081   ← 渐变被误判
新     0.037   0.004   0.234   0.267   0.435   0.004   ← 误判关掉
```

真实暗部该拿的照拿（黑裤甚至从 0.420 升到 0.435），渐变不再被误伤 ——
7 档 × 纯白/纯黑/渐变 的回归现在是**全零改动**。

## 先看基准线：只压缩（对照）

风格化的图（AI 生图、柔光人像、大面积虚化）有个共性：**它本来就柔**。
这时候光看"增强后的成品"，很容易得出两种互相矛盾的结论 ——
要么觉得「跟原图差不多」，要么觉得「糊/颜色不对」。两种感觉都不算错，
错的是**没有基准线**：你比的是"增强结果 vs 你记忆里的原图"，
而不是"同一张图、同样尺寸、同样编码下，处理过和没处理过到底差多少"。

界面上的 **「只压缩（对照）」** 按钮就是干这个的：**一个像素都不改**，
只按当前选定的尺寸策略和输出格式重新编码一遍。把它和「开始处理」的结果
摆在一起（同一个尺寸策略、同一个格式），差别就是你真正买到的东西。

```powershell
# 命令行等价写法
python enhance.py -i 图.jpg -o out\ --compress-only --format jpeg
```

输出名和增强那条路**不同后缀**，所以两条路可以写进**同一个目录**、不会互相覆盖：

```
out\图_cmp.jpg      ← 只压缩（对照）
out\图_enh.jpg      ← 增强
```

尺寸策略选「缩到长边」时，`_cmp` 是原图直接缩到 750 再编码；`_enh` 是在 750 上
锐化后再编码。两者像素尺寸完全相同，只有"有没有锐化"这一处差别 —— 这样对比才成立。
报告也分开写（`_处理报告.csv` / `_处理报告_只压缩.csv`），两次跑的读数不会互相冲掉。

实测（1200x1200 商品图，尺寸策略 = 保持原像素、不缩图）：

| 走哪条路 | 像素改动 | 体积 | 说明 |
|---|---|---|---|
| 只压缩 + PNG | **逐像素最大差 0** | 1271 KB | 零损失，仅换封装 |
| 只压缩 + JPEG q92 | PSNR **48.7 dB** | **112 KB**（-91%） | 肉眼看不出，体积只有 PNG 的 9% |
| 增强 + JPEG q92 | 见「尺寸策略」一节 | 同量级 | 相对上面那行多出来的，才是增强 |

⇒ 判断方法：**先跑一次「只压缩」当基准，再跑「开始处理」**，两张一起看。
如果两张的差别你都看不出、也不在意，那这一档就不必开 —— 省下的时间是真的，
没有损失可言。

16 张真实商品图（尺寸策略 = 缩到长边 750，档位 = 全面清晰）实测，
**相对「只压缩」这条基准线**：

| 指标 | 中位增益 |
|---|---|
| HF 锐度 | **+25.5%** |
| 局部对比 | **+3.8%** |

单张离散度很大（HF 从 +2.4% 到 +47.1%）—— 这就是为什么"有的图效果明显、
有的图看着没动"：**图上本来有多少中梯度细节，决定锐化有多少东西可锐**。
只压缩那道基准线能让你一眼看出这张图属于哪一类，而不是靠感觉猜。

> 注意「只压缩」不会读预设里的锐化参数，**只认尺寸策略和格式**。
> 想让它真的缩像素就选"缩到长边"；选"保持原像素"时它连尺寸都不会动。

## 尺寸策略：三条路，任选一条把「清晰度」和「文件大小」都拿到

全篇最反直觉的一条：**把图缩小再锐化，不但文件小 94%，清晰度还高 56%。**
但如果你不想动像素 —— **也行，效果几乎一样。**

界面第 3 步有三个选项（三选一）：

| 策略 | 干什么 | 像素 | 效果（16 张真实图，按 750 显示量） |
|---|---|---|---|
| **缩到长边 750** | 先缩，再在 750 上锐化 | 750 | HF **+32.5%**、局部对比 +5.2%、体积 **-94%** |
| **保持原像素，按该宽度归一** | 不缩，把半径/门限换算到 750 尺度 | 原样 | HF **+27.7%**、局部对比 **+6.9%**、体积 -90% |
| 都不做 | 按原图像素尺度处理（历史行为） | 原样 | HF +20.6%、局部对比 +3.9% |

两条新路的清晰度都明显高于历史行为，差别只在「要不要真的缩像素」：
缩图那档 HF 更高，不缩图那档**局部对比反而最高**（人眼判断清不清楚主要看局部对比）。

> 想保原始像素又想看清楚 ⇒ 选第二个（`保持原像素，按该宽度归一`）。
> 不在意尺寸、只要最好看 ⇒ 选第一个（`缩到长边 750`）。

### 为什么会这样

锐化的半径是**固定的 3 像素**，缩放会把这个物理尺度整个改掉。
平台展示时又会把图缩到自己的显示宽度（常见 750），于是：

```
旧路子：1200px 上锐化 → 平台缩到 750 展示
        ⇒ 锐化出来的那层高频，大部分被重采样吃掉了
新路子：先缩到 750 → 在 750 上锐化 → 直接就是这个尺寸
        ⇒ 锐出来的频率正好落在最终显示的那张图上，一点不浪费
```

### 实测（16 张真实商品图，都按 750 显示尺寸测量）

| 指标 | 旧：先锐化后缩 | 新：先缩后锐 | 变化 |
|---|---|---|---|
| HF 锐度增益（中位） | +20.6% | **+32.2%** | 高 56% |
| 局部对比增益（中位） | +3.9% | **+5.2%** | 高 33% |
| 16 张合计体积 | 25.7 MB（PNG） | **1.5 MB**（JPEG q92） | **省 94%** |

单张的例子（`对比感增强` 档）：

```
1-top-left      旧 +12.5%  ->  新 +18.5%
3-bottom-left   旧 +24.7%  ->  新 +39.6%
4-bottom-right  旧 +37.7%  ->  新 +47.0%
```

### 各种「变小」的方式，效果对比

同一张 1200px 图，四条路都走到「平台最终显示」这一步再量：

| 方式 | HF 增益 | 局部对比 | 文件大小 |
|---|---|---|---|
| 1200 锐化 + PNG（旧默认） | +15.5% | +4.0% | 1189 KB |
| 1200 锐化 + JPEG q92 | +15.5% | +4.0% | 121 KB |
| 缩 900 再锐化 + JPEG | +9.6% | +2.0% | 75 KB |
| **缩 750 再锐化 + JPEG** | **+24.2%** | **+5.2%** | **55 KB** |

⇒ 缩 900 是个**两头不讨好**的档位：它既没缩到平台宽度、锐化的频率又被打了一次折，
增益反而比不缩还低。**要么缩到 750，要么就别缩。**

### JPEG 会损失多少（同一张图，只改编码方式）

| 编码 | PSNR | 体积 | HF 保留 | 局部对比保留 |
|---|---|---|---|---|
| PNG（无损） | 无损 | 1644 KB | 1.00x | 1.000x |
| JPEG q95 | 45.4 dB | 294 KB | 1.01x | 1.000x |
| **JPEG q92（默认）** | **44.1 dB** | **212 KB** | **0.99x** | **1.000x** |
| JPEG q88 | 43.0 dB | 170 KB | 0.98x | 0.999x |
| JPEG q85 | 42.5 dB | 146 KB | 0.97x | 0.998x |

44 dB 是什么概念：肉眼看不出差别（一般认为 40 dB 以上就够，45 dB 是「完全无感」）。
**q92 保住了 99% 的 HF 和 100% 的局部对比，体积只有 PNG 的 13%。**

### 怎么用

界面上默认就开着（第 3 步里那行），也可以命令行：

```powershell
python enhance.py -i 图.jpg -o out\ --shrink 750 --format jpeg
```

- `--shrink 750` 长边缩到 750 再锐化（像素真的变小）
- `--display-width 750` **不缩像素**，只把半径/门限换算到 750 显示尺度
- 两个参数二选一；都不给 = 按原图像素尺度处理（历史行为）
- `--shrink 900` 上面那张表里的两头不讨好档，除非你的平台就是 900 宽
- `--format png` 要无损时用，体积会大 7~8 倍
- 尺寸怎么选：**跟着平台显示宽度走**。淘宝/拼多多详情页常见 750，主图 800；
  拿不准就用 750，平台再怎么缩也缩不狠了

## 它怎么判断「值不值得跑」

三个可以算出来的数，无模型、无人眼、无框选：

| 数 | 含义 | 范围 |
|---|---|---|
| **带内占比** | Sobel 幅度落在锐化门限带 [0.045, 0.20) 的像素比例 | 平坦白底 0.036~0.055；带材质/褶皱/链条 0.12~0.46 |
| **主体遮罩覆盖** | 「暗且中性灰」区域的面积占比 | 白底商品 0；有主体 0.1~0.9 |
| **链路存活增益** | 过完「缩到 750px + JPEG q85」之后还剩多少高频提升 | 噪声级 <3.5%；肉眼可辨 >8% |

```
跑     带内占比 >= 0.070  且  链路存活增益 >= 8%
跳过   带内占比 <= 0.055  且  遮罩 <= 1.5%
其余   边界（照跑，只是标注出来）
```

在一批真实电商主图上实测：**跑 44 / 边界 9 / 跳过 6**，
判定精确率 97.7%，漏放 0 张。跳过的那批共同特征是「大片平坦白底 + 纯文字/徽章」，
链路存活增益只有 +1.7~2.3%。

## 为什么小

它不加载任何权重、不做任何生成，全部逻辑就是 1676 行 Python
（`enhance.py` 1068 + `ui.py` 608）：
导引滤波分解、门限锐化、保边中频分解、三个颜色门、一个统计判据。

正因如此：**2048px 的图 0.25 秒一张**，纯 CPU。
也正因如此，它做不到「把丢掉的细节变回来」—— 像素里没有的东西，它变不出来。
它能做的是把已经在那里的结构变清楚。

如果哪天真要接生成模型（重绘细节），那是另一个东西，会带来另一套代价：
权重几百 MB 到几 GB、要显卡、输出不可复现、以及最重要的 —— 它会改内容。

## 自检的 9 条（跑 `--selftest`）

验证的不是「结果好不好看」，而是「不许发生的事有没有发生」：

1. 纯色平坦图，锐化后零改动
2. 平滑渐变（无边缘），零改动
3. 有边缘的图，确实变锐
4. 极小图（8/16/23/24/25/40 px）不崩
5. 遮罩形状正确且值域在 [0,1]
6. `--amount 0` 时严格恒等
7. 中文路径读写往返一致
8. 判定器输出三档之一且结果可重复
9. 整体亮度漂移 < 1%

第 1、2 条是整个工具的立身之本：平坦区一个字节都不动，
所以天空、白底、墙面不会出现「AI 爬纹」。

## 参数备忘（什么时候才需要调）

| 参数 | 默认 | 什么时候动 |
|---|---|---|
| `--amount` | 2.0 | 觉得不够锐就往上（3.0 已经很硬），觉得过锐就往下 |
| `--scale` | 1.0 | 需要更大尺寸时用，纯 Lanczos 插值，不会增加细节 |
| `--shrink 750` | 界面默认开 | 长边缩到多少再锐化。改这个值之前先读「先缩后锐」那节 |
| `--display-width 750` | 与 `--shrink` 二选一 | 不缩像素时的等效显示宽度。要保原始分辨率就用它 |
| `--format jpeg` | 界面默认 JPEG | 要无损改 `--format png`，体积会大 7~8 倍 |
| `--compress-only` | 关 | 只重新编码、不做任何增强。要和增强结果做**对照**时开 |
| `--obj-mode enhance` | 不用 | 旧档，物件也锐化。**实测会把暗部细节一起沉下去，不要用** |

其余参数（遮罩门限、锐化门限、过冲容差）都写在代码里带着实测注释，
不要凭感觉改 —— 每一个值的来历都在注释里，包括踩过的坑。

## 已知边界

- **不做生成**：糊掉的细节不会被「补」出来，只会让还在的结构更清楚。
- **不碰颜色**：全程只动 Y 通道，色相/饱和度/白平衡一个都不改。
- **暗部**：「推荐 / 轻微」两档下暗部物件保持原样（刻意为之 —— 早期直接压黑会把细节一起沉掉）。
  想要暗部更清楚用「暗部更清晰 / 全面清晰」：掩膜叠了局部标准差当结构门，
  只提有纹理的暗部，纯黑平坦区不动。实测黑包高频 +30%、裤 +38%，颗粒只涨 0.05%。
- **对比感**：只有「对比感增强」这一档会拉开中频明暗（局部对比最高 +8%），
  代价是 0.08%~0.18% 的像素有极轻微光晕（最大过冲 9/255）。其余六档过冲 ≤3/255。
- **放大**：`--scale` 是插值，不是超分。要真超分得接模型，那属于另一条路。
