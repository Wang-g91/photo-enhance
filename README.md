# 图片增强

纯 CPU 的电商图片清晰化工具：一个 `enhance.py` 核心 + 一个双击就开的图形界面。
不加载任何权重、不做生成式重绘，只把**已经在图里的结构**变清楚。

一个文件（`enhance.py`），纯 CPU，无模型、无权重、无显卡要求。

**它做什么**

1. 按图自动判断值不值得处理 —— 白底平坦图直接用原图，不给平台二次压缩添乱
2. 门限保边锐化 —— 只锐有结构的边缘，平坦区增益严格为 0
3. 分区 —— 人物/主体区锐化，暗且中性的物件区保持原样
4. 批量 —— 扫一个目录，跑的跑、跳的跳过，附 CSV 报告

**它不做什么（这些都是刻意的）**

不重建、不重绘、不补细节、不改颜色、不动全局曲线、不生成内容。
只动锐度，且只在有结构的地方动。

为什么强调这一条：早期版本试过接 NR/超分那条路，结论是那条路会重绘内容，
表现就是「糊、颜色不对、失真」。所有失真的源头都来自「让它生成」这件事本身。

## 仓库里有什么（源是源，工具是工具）

**仓库 = 工具本体，一个字节的真实素材都没有。** 磁盘上两者物理隔开：

```
<工作区>\                          ← 不进仓库
├─ 图片增强\                        ← Git 仓库根目录，只有工具
│   ├─ enhance.py    ui.py   启动.bat   README.md   LICENSE
│   ├─ make_sample.py              ← 合成图生成器（仓库里唯一的"图"来源）
│   ├─ 标定\                        ← 本机标定脚本（写死本机路径，已 gitignore）
│   └─ _sample\                     ← 合成图（可随时重生成，已 gitignore）
└─ _本机素材\示例\                   ← 真实测试原图，在仓库**外面**
```

| 进仓库 | 不进仓库 |
|---|---|
| `enhance.py` `ui.py` `启动.bat` `README.md` `LICENSE` `make_sample.py` | 任何真实 `.png`/`.jpg`、`_本机素材/`、`标定/`、`_sample/`、输出目录、`_*.json` |

原因很直接：**工具可以公开，商品素材不可以。** 工具代码里也不含任何指向
具体项目、具体店铺的路径与名字。仓库里的图只有一种来源 —— 现场合成：

```
python make_sample.py
```

## 用法（两种）

**图形界面**（推荐，双击就行）

```
双击「启动.bat」
```

界面里选图 → 选预设 → 点开始。原图只读，输出写到旁边的 `_增强` 文件夹。

**命令行**

```powershell
# 单张（全自动分流）
python enhance.py -i 图.jpg -o out\

# 批量（一个目录）
python enhance.py -i 我的图目录 -o out\

# 只看判不判，不出图
python enhance.py -i 图.jpg --judge

# 附各亮度档读数
python enhance.py -i 图.jpg -o out\ --report

# 不做分流，一律处理
python enhance.py -i 图.jpg -o out\ --force

# 用预设（等价于界面里选那一档）
python enhance.py -i 图.jpg -o out\ --preset 全面清晰
python enhance.py --list-presets

# 自检（不需要外部图，读的是合成样本）
python enhance.py --selftest
```

`-o` 不写的话，单张默认输出到 `out\`，目录默认输出到 `<目录名>_增强\`。

## 预设（六档）

| 预设 | 干什么 | 适用 |
|---|---|---|
| **推荐** | 人物区锐化，暗且中性的物件区保持原图 | 最稳，任何图都不会失真 |
| **暗部更清晰** | 给有纹理的暗部加局部锐化，平坦黑背景不动 | 黑包/黑衣/阴影想更清楚 |
| **救糊图** | 给"发虚发软"的区域补锐度 | 原图本来就偏软 |
| **全面清晰** | 暗部 + 糊区一起开 | 想一次到位 |
| **轻微** | 只补一点点 | 图已经很干净 |
| **清晰 + 放大2倍** | 全面清晰 + 2 倍 Lanczos | 要更大尺寸 |

预设是可复现的固定参数，不是"感觉调一下"。每一档的实测读数（HF 高频变化，
区域按坐标定位，含耳环这种小件）：

```
预设            脸    耳环   黑衣   黑包   黑裤   蓝天   亮度漂移
推荐          +40%   +27%   +19%    +9%    +6%    +2%    -0.20%
暗部更清晰     +53%   +30%   +45%   +32%   +45%    +3%    -0.29%
救糊图        +44%   +31%   +22%   +12%    +9%    +2%    -0.15%
全面清晰      +59%   +36%   +50%   +37%   +49%    +3%    -0.29%
轻微          +27%   +19%   +15%    +6%    +5%    +1%    -0.20%
```

三条硬约束在每一档都成立：**平坦区零改动、亮度漂移 < 1%、颜色不动**。

蓝天 +1~3% 不是"爬纹"：那是天光渐变本身的软过渡，在锐化门限带内，
数值小且不随档位放大（档位从轻微到全面清晰只从 +1% 到 +3%），
真实平坦白底（合成样本）是严格 0。颗粒列（平坦区 std 变化）五档全是 1.00x。

## 局部自适应是怎么做的（暗部 / 糊区）

两个问题分开解，都是**逐像素掩膜**，不看全图、不用模型：

**暗部更清晰** —— 掩膜 = 「此处暗」×「此处有结构」。
只看亮度是不够的：纯黑的阴影空洞没有东西可提，硬提只会把噪点拉出来。
所以叠一层局部标准差当结构门。判据相对梯度而不是绝对梯度，
这样暗处纹理才进得来（绝对门限对亮部合适，暗部会被全挡在门外）。

**救糊图** —— 掩膜 = 「细节扛不住重采样」×「有内容」。
判据是**降采样再升采样后的高频损失**：

```
清晰图    损失 0.17 ~ 0.41   （细节丰富，一缩一放丢掉一大半）
糊图      损失 0.05 ~ 0.08   （本来就没细节，丢无可丢）
```

这个量**与内容多少无关**，只与"是否已经糊了"有关，所以整图均匀发虚也认得出来。

标定实测（细节损失中位）：

```
            清晰   模糊0.8   模糊1.5   模糊2.5
人像       0.171    0.114     0.076     0.055
商品图     0.407    0.146     0.047     0.015
文字图     0.229    0.119     0.049     0.023
```

三档单调，三种内容类型都成立。

**物件保护与加成的关系（这里踩过一个坑，写下来）**：
物件保护的初衷是"别把包当脸一起锐"，做法是暗且中性的区域不吃**基础锐化**。
一开始它连暗部/糊区加成一起削了 —— 实测「暗部更清晰」档在黑包/黑裤上
78%~83% 的加成被吃掉，预设名字写着"更清楚"，拿到的却是接近推荐档的数字。
现在两者分开：**基础锐化被物件保护挡，单独算出来的加成不挡**。
所以黑包该被保护的原样被保护（不爬纹），而"这里暗且有纹理"该拿的清晰度照拿。

**能补回多少（实测，别抱不切实际的期望）**：unsharp 的物理上限大约是 ——
轻糊（sigma 0.8）能补到 **~75%**，中度（1.5）**~33%**，重度（2.5）**~15%**。
再往上加只会出光晕和假边，不会真的把信息变回来。

## 它怎么判断「值不值得跑」

三个可以算出来的数，无模型、无人眼、无框选：

| 数 | 含义 | 范围 |
|---|---|---|
| **带内占比** | Sobel 幅度落在锐化门限带 [0.045, 0.20) 的像素比例 | 平坦白底 0.036~0.055；带材质/褶皱/链条 0.12~0.46 |
| **主体遮罩覆盖** | 「暗且中性灰」区域的面积占比 | 白底商品 0；有主体 0.1~0.9 |
| **链路存活增益** | 过完「缩到 750px + JPEG q85」之后还剩多少高频提升 | 噪声级 <3.5%；肉眼可辨 >8% |

```
跑     带内占比 >= 0.070  且  链路存活增益 >= 8%
跳过   带内占比 <= 0.055  且  遮罩 <= 1.5%
其余   边界（照跑，只是标注出来）
```

在一批真实电商主图上实测：**跑 44 / 边界 9 / 跳过 6**，
判定精确率 97.7%，漏放 0 张。跳过的那批共同特征是「大片平坦白底 + 纯文字/徽章」，
链路存活增益只有 +1.7~2.3%。

## 为什么小

它不加载任何权重、不做任何生成，全部逻辑就是 1130 行 Python
（`enhance.py` 750 + `ui.py` 382）：
导引滤波分解、门限锐化、两个颜色门、一个统计判据。

正因如此：**2048px 的图 0.25 秒一张**，纯 CPU。
也正因如此，它做不到「把丢掉的细节变回来」—— 像素里没有的东西，它变不出来。
它能做的是把已经在那里的结构变清楚。

如果哪天真要接生成模型（重绘细节），那是另一个东西，会带来另一套代价：
权重几百 MB 到几 GB、要显卡、输出不可复现、以及最重要的 —— 它会改内容。

## 自检的 9 条（跑 `--selftest`）

验证的不是「结果好不好看」，而是「不许发生的事有没有发生」：

1. 纯色平坦图，锐化后零改动
2. 平滑渐变（无边缘），零改动
3. 有边缘的图，确实变锐
4. 极小图（8/16/23/24/25/40 px）不崩
5. 遮罩形状正确且值域在 [0,1]
6. `--amount 0` 时严格恒等
7. 中文路径读写往返一致
8. 判定器输出三档之一且结果可重复
9. 整体亮度漂移 < 1%

第 1、2 条是整个工具的立身之本：平坦区一个字节都不动，
所以天空、白底、墙面不会出现「AI 爬纹」。

## 参数备忘（什么时候才需要调）

| 参数 | 默认 | 什么时候动 |
|---|---|---|
| `--amount` | 2.0 | 觉得不够锐就往上（3.0 已经很硬），觉得过锐就往下 |
| `--scale` | 1.0 | 需要更大尺寸时用，纯 Lanczos 插值，不会增加细节 |
| `--obj-mode enhance` | 不用 | 旧档，物件也锐化。**实测会把暗部细节一起沉下去，不要用** |

其余参数（遮罩门限、锐化门限、过冲容差）都写在代码里带着实测注释，
不要凭感觉改 —— 每一个值的来历都在注释里，包括踩过的坑。

## 已知边界

- **不做生成**：糊掉的细节不会被「补」出来，只会让还在的结构更清楚。
- **不碰颜色**：全程只动 Y 通道，色相/饱和度/白平衡一个都不改。
- **暗部**：「推荐 / 轻微」两档下暗部物件保持原样（刻意为之 —— 早期直接压黑会把细节一起沉掉）。
  想要暗部更清楚用「暗部更清晰 / 全面清晰」：掩膜叠了局部标准差当结构门，
  只提有纹理的暗部，纯黑平坦区不动。实测黑包高频 +69%、裤 +36%，颗粒只涨 2%。
- **放大**：`--scale` 是插值，不是超分。要真超分得接模型，那属于另一条路。
